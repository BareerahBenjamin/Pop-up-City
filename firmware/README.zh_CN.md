# Pop-up City 固件接入

分区、存档与烧录统一遵循指定Starter仓库的herstory-event-v1契约，详见[统一保档规则](persistence-policy.zh_CN.md)。旧planet-preview布局不再作为分区依据。

这里已包含产品整合工程与独立 C 核心模块，**尚不是完整可交付固件**。硬件参考来自 `folotoy_herstory/folotoy`，其当前 planet-preview 入口仍是屏幕诊断。此次未修改外部工程、分区、身份或设备数据。

`components/pop_city_core` 实现开机/页面优先级、待决操作核对、按键动作分配、长短按互斥和通知持久消费边界。已提供 ESP-IDF 组件注册；[个人存储适配器](storage.zh_CN.md)已实现并通过主机故障测试；原生入口、网络与分条画面渲染已编译通过，完整界面和业务连接仍待完成。

在仓库根目录运行 `sh firmware/tools/validate.sh`。严格编译实际 C 源码，启用地址及未定义行为检查，执行88条核心断言、1603条存储断言及上游源码契约检查；macOS另运行83条[云端及开机流程断言](startup-integration.zh_CN.md)，并验证BLUFI输入和Wi-Fi扫描模型。这是主机测试，不是 ESP32 构建或实机验收。

接入约束：

- 单一应用工作任务持有状态并负责存储/网络，按键回调只入队；只有验证过的服务器事实/回执才能更新操作结果。
- 初始化传入持久 Hello 标记及之前是否已绑定。新绑定成功进入 PC_BOUND 等待 OK；已绑定开机按 Hello 历史进入。先保存跳过标记，再调用 pc_hello_saved(true)。
- 发请求前先保存操作编号。网络超时保留 unresolved，查询同一编号；操作开始和结果回调由适配器负责校验，核心不直接发请求或验证近距离。
- key_policy 接收原始按下/抬起事件；也可以直接适配已有 BSP CLICK/LONG 事件，但两条路径不可重复处理。长按阈值500ms，与参考 BSP 一致。切页时屏蔽入口按键直到释放。选人只返回动作，不进入 loading。
- feedback 结构须清零或从持久存储恢复。pc_feedback_open 接收服务器已确认的会话UUID和同步持久保存回调，保存失败不允许反馈，同会话保留游标；只能用服务器确认的新UUID换会话。调用前必须验证签名、接收设备、会话和校准后的服务器时间。
- PC_FEEDBACK_PULSE_ACK 表示消费编号已经保存，可以亮起1000ms后确认。ACK_ONLY只确认不亮起；断网使消费失效。先保存再亮起的取舍是避免重播，保存后立刻掉电可能少一次视觉反馈。
- 近场回执和云通知须共用一个反馈入口，不可各亮一次。HTTP字段、UUID和未决操作持久化仍由适配器负责，核心不替代完整协议校验。
- 屏幕/LVGL操作遵守BSP锁；网络不能阻塞动画与按键。电源仅控制硬件；普通页面长按OK（500ms）开关说明，短按OK及开机/处理限制保持原规则。

## 原生整合工程（2026-10-19）

根目录已建立产品整合工程，编译参考 BSP 原样复用的屏幕／按键驱动、网络任务和初始 UI 入口。155 张已确认 PNG 与 168 张欢迎动画帧转为 2,068,528 字节 RGB565 行程压缩数据；渲染仅需 4,800 字节 DMA 分条缓冲，等待传输完成才复用，每张图片的逐像素校验均通过。当前入口仍是未完成的引导／名字／Hello 框架；其余动画、完整颜色映射、个人星球获取、业务操作及出厂身份初始化尚未接齐，静态或占位框架不代表最终界面。product-readiness.json 保持未通过，跨电脑打包工具拒绝生成正式交付包。
