- **版本：** v1.0
- **负责人：** Herstory 项目维护者
- **状态：** 本地实现与验证完成，未部署
- **最后更新：** 2026-10-19

## 行为

已取消活动退出活动页卡片、月历格子、月历当日安排、一天／三天／一周时间表和地图活动列表；不计入这些模块的活动数量。后台仍能查看取消原因、恢复发布或删除活动。已取消活动的原详情链接保留，便于了解取消状态。

此前日历将 `published` 与 `cancelled` 一并展示，跨日活动会出现在每个实际占用日期，因此取消后仍会多日显示。现在这些安排只展示 `published`。★★★★★（源码及跨日、已取消活动回归验证。）

## 后台操作

后台 → 活动 → 对应活动「删除活动」→ 确认框核对标题、时间与地点 →「确认删除活动」。默认焦点为「保留活动」，Escape 或取消均不删除。提交中禁止重复操作；失败保留确认框、显示错误并允许重试。成功后刷新列表，将焦点移至后台活动标题。

删除后活动退出前台及后台列表、成员发起活动列表和设备待参加活动列表；详情、封面、二维码、修改、报名和收藏入口不再开放。管理员仍可通过审计接口查询历史操作。

删除采用独立删除记录，保留原活动、报名、收藏、签到、设备回执及成长记录，不自动撤销已经获得的成长资产。页面不提供恢复删除入口。取消活动原有的业务及成长规则保持原逻辑。★★★★★（删除前后成长资产及签到事实对照测试。）

## 接口与迁移

| 项目 | 约定 |
| --- | --- |
| 接口 | `DELETE /api/admin/events/:id` |
| 权限 | 仅管理员，继续执行同源校验 |
| 请求体 | JSON：`{"confirm_title":"确认框中的活动名称"}` |
| 名称变化 | 返回409，要求刷新后重新确认 |
| 重复删除 | 返回200；不重复写删除审计 |
| 未知活动 | 返回404 |
| 审计 | `event_audit.action = 'delete'`，与删除记录在同一事务提交 |

新增 `0012_event_deletions.sql`，建立只追加的 `event_deletions(event_id, deleted_by, deleted_at)`。既有迁移及事件状态字段不重写。删除记录不向公开活动接口输出。

本地已先生成 `backup-before-event-delete-20261019.sqlite` 一致性备份，再执行 `npm run migrate` 并重启3300服务。备份位于被 Git 忽略的本地数据目录。未来部署也须先备份、执行迁移、重启；本次未部署。
